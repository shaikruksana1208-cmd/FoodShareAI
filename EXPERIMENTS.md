# FoodShare AI Experiments

## Reproduce

From the project root in PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pytest -q
python run_experiments.py
```

The experiment reads only `experiments/data/synthetic_donations.csv` and `experiments/data/synthetic_requests.csv`. It does not read the live SQLite database. The input files and output rows are labeled synthetic.

## Methods Compared

- **Greedy baseline:** at each step selects the currently feasible pair with the highest score.
- **Exhaustive search:** tries each feasible donation or the unmatched action for each request, tracking remaining inventory. It maximizes the number of fully satisfied requests, then total compatibility score.

Both use the same hard constraints and scoring method. A high score cannot override unsafe, expired, unavailable, category-incompatible, unit-incompatible, or insufficient food. See [AI_ALGORITHM.md](AI_ALGORITHM.md) for the full state, actions, objective, and complexity definition.

## Metrics

- Valid matches: count of fully fulfilled requests.
- Quantity fulfilled: sum of allocated quantities.
- Fulfillment rate: fulfilled quantity divided by the total quantity of well-formed open requests.
- Rejected pairs: every pair that failed a hard check before allocation.
- Invalid matches: selected assignments that fail pair validation.
- Double allocations: a request assigned more than once or a donation assigned beyond its initial quantity.
- Constraint violations: invalid assignments plus duplicate requests and donor over-allocation.
- Execution time: `perf_counter` duration; summary is the mean of 25 runs and includes population standard deviation.

## Observed Result

Generated by the actual experiment runner on the checked-in fixed synthetic dataset. These are not real donations or generalized guarantees.

| Method | Mean matches | Mean quantity | Valid-demand fulfillment | Invalid | Double allocations | Violations | Mean runtime |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Greedy | 5 | 16 | 41.0256% | 0 | 0 | 0 | 0.005056308 s |
| Exhaustive search | 6 | 24 | 61.5385% | 0 | 0 | 0 | 0.050691204 s |

In this one synthetic case, search assigned one more request and eight more quantity units, while taking longer. Do not claim it is always better. Execution timings vary with machine load.

## Files Produced

`run_experiments.py` regenerates:

- `experiments/results/experiment_runs.csv`
- `experiments/results/experiment_summary.csv`
- `experiments/results/allocation_details.csv`
- `experiments/results/allocation_quality.png`
- `experiments/results/allocation_timing.png`

The experiment suite is separate from the live app database at `instance/foodshare.sqlite3` (or the path configured by `FOODSHARE_DATABASE`).
